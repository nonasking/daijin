# daijin 데모 영상 기획: "말 한마디가 도시 반대편에서 사고를 친다"

> 컨셉 한 줄: **다이진은 장난꾸러기 신이다.** 내가 A에서 한마디 하면, 서로 다른 망에 있는 B와 C에서 뭔가가 물리적으로 벌어진다.
> (이름 출처인 스즈메의 다이진처럼, 명령을 받으면 어디론가 가서 사고를 치고 돌아와 보고한다.)

포트폴리오지만 딱딱한 기능 나열 대신 **에피소드형**으로 간다. 기술 포인트는 자막 한 줄로만 얹는다.

---

## 1. 구조 검증: 세 개의 망에서 되는가 → 된다

| 위치 | 망 | 장치 | 근거 |
|---|---|---|---|
| A (집) | 집 WiFi | 나 + daijin 음성 디바이스 + 맥(브레인) | 맥은 아웃바운드만, 집에 둔다 |
| B | 아이폰 1 핫스팟 | dev1 (서보 + 릴레이 + 부저) | 노드는 클라우드 브로커로 TLS 아웃바운드만 |
| C | 아이폰 2 핫스팟 | dev2 (서보 + 부저) | 위와 같음 |

모든 장치가 HiveMQ 클라우드(EU)에서 만나기 때문에 **같은 망에 있을 필요가 처음부터 없었다.** 확인이 필요했던 건 노드 쪽 두 가지였고, 둘 다 이번에 손봤다.

- **노드가 한 망만 기억하던 문제**: WiFiManager는 마지막 접속 정보 하나만 저장해서, 노드를 다른 핫스팟으로 옮기면 매번 포털 설정이 필요했다. → `secrets.h`에 집/핫스팟1/핫스팟2를 넣고 WiFiMulti로 잡히는 곳에 자동 접속, 전부 실패할 때만 포털로 폴백.
- **ACK 오답**: `dev.sh`가 retained된 직전 ACK를 먼저 읽어 `led:red`에 `pong`이 찍히던 경쟁 조건. → 구독을 먼저 열고(-R) publish 하도록 수정, 가짜 노드로 재현 후 통과 확인.

### 촬영 전 꼭 확인할 물리 조건
- **ESP32는 2.4GHz 전용.** 아이폰 설정 > 개인용 핫스팟 > **"호환성 최대화" ON.** 이거 안 켜면 노드가 핫스팟을 아예 못 본다.
- 핫스팟 아이폰은 **충전기에 물려둔다.** LTE 핫스팟 + 4K 녹화 동시면 배터리가 빠르게 준다.
- 노드가 붙어 있으면 아이폰 화면이 잠겨도 핫스팟은 유지된다. 단 **노드를 켜기 전에 핫스팟 화면을 열어두는 게** 안전하다(클라이언트가 없으면 90초쯤 뒤 꺼짐).
- 왕복 지연은 **6~22초**가 정직한 수치다. 숨기지 말고 화면에 타이머를 띄운다(아래 편집 항목).
- 릴레이는 **5V USB 라인만** 끊는다. 220V는 이 영상에서 안 한다(README 안전 원칙 그대로).

## 2. 에피소드 아이디어 (트릭스터 시리즈)

각 에피소드 = 내 한마디(A) → 다이진의 대답 → B/C의 물리 반응 → 관제 화면 한 줄. 아래에서 3~4개만 골라 60~90초로 붙인다.

### EP1. "회사 와이파이 꺼버려" ★ 메인 개그이자 기술 하이라이트
- **B의 dev1이 자기 전원을 스스로 끊는다.** 보드의 5V 라인을 릴레이 **NC 접점**에 통과시켜 두면, `relay:pulse:1000`에 접점이 열리는 순간 보드가 죽고, 코일이 풀리며 접점이 닫혀 다시 켜진다. 자기 손으로 자기 목을 조르고 부활하는 그림.
- 화면에 벌어지는 일: dev1 LED 꺼짐 → 30초 안에 브로커 LWT가 offline 마킹 → **fleet_watch가 알아채고 다이진이 먼저 말한다** "dev1이 오프라인 됐어… 아, 업타임 5초로 돌아왔네, 재부팅했나 봐."
- 왜 이게 하이라이트인가: 명령 실행뿐 아니라 **장애 감지 + 능동 보고**가 한 컷에 다 나온다. 포트폴리오의 진짜 차별점.
- 배선: USB 케이블 하나 잘라 빨간선(5V)만 릴레이 COM과 NC에 연결. 다른 선은 그대로 이음.
- 더 문자 그대로 하고 싶으면: USB 전원 소형 여행용 공유기를 릴레이 뒤에 두고 그 공유기에 dev1을 붙인다. 결과는 같다.

### EP2. "상사 차 펑크 내" → 풍선 타이어
- C의 dev2 서보 혼에 **바늘을 테이프로 고정**, 컵에 꽂아둔 풍선(타이어 그림 붙임)을 `poke:120:600`으로 찌른다. **펑 소리**가 영상의 오디오 훅.
- SG90 토크가 약하니 풍선은 빵빵하게, 바늘은 뾰족한 걸로, 각도는 현장에서 맞춘다.
- 대안(풍선이 잘 안 터지면): 서보가 도미노를 밀어 장난감 자동차를 넘어뜨린다.

### EP3. 거절 컷 (안전 설계를 개그로)
- "상사 차 **진짜로** 펑크 내" → 다이진: "그건 안 돼. 대신 풍선은 터뜨려 줄게." → EP2로 이어진다.
- 브레인 프롬프트의 "파괴적 작업은 확인" 원칙이 자연스럽게 노출된다. 이 컷은 대본 없이 실제 응답을 쓴다(연출 티가 나면 안 된다).

### EP4. "회의 빠져나오게 전화 온 척 해줘"
- B의 dev1 `buzz:alarm`. 부저 소리를 전화벨처럼 쓰고, 나는 "어, 급한 전화네" 하고 나간다.
- 가벼운 컷. 부저 하나로 되니 준비 비용이 거의 없다.

### EP5. "전부 불 꺼" (브로드캐스트)
- `all led:off` 한 번에 A/B/C 세 곳 LED가 동시에 꺼진다. 3분할 화면에서 동시에 꺼지는 게 포인트.
- 기술 자막: "토픽 하나로 전 노드 브로드캐스트".

### EP6. "다들 어디 있어?" ★ 크로스 네트워크 증명 컷
- `fleet.sh`가 각 노드의 **접속 망 이름**을 보여준다(이번에 status에 ssid 추가). 관제 화면에 `dev1 · 망 민성의 iPhone`, `dev2 · 망 ○○의 iPhone`, `daijin · 집` 이 나란히 찍히는 장면 하나로 "서로 다른 망" 주장이 증명된다.
- 다이진 대사 예: "dev1은 네 아이폰에 붙어 있고, dev2는 다른 아이폰에 있어. 셋 다 온라인이야."

### EP7. 에필로그
- "오늘 수고했어, 다들 몇 도야?" → 다이진이 노드들 칩 온도를 읽어 말한다. 사고 치고 다니던 신이 마지막엔 식구들 안부 묻는 톤으로 끝.

### 물리 장치가 아니어도 되는 액추에이터
- **맥 자체가 노드다.** 브레인이 Bash를 쓰니 "B 화면에 사진 띄워", "C에서 노래 틀어"는 맥 두 대만 있으면 코드 없이 된다(`open`, `say`, `afplay`).
- 폰 알림: 브레인이 이메일을 보내면 폰이 울린다(Gmail 연동 시).
- 화면 없는 노드라면 **LED 색 자체가 표정**이다. 다이진이 삐치면 전 노드가 빨강.

## 3. 촬영 셋업 (혼자서도 가능)

```
A(집)   : 나 + daijin 디바이스 + 맥
          맥: QuickTime 화면 녹화(console.sh 터미널 + 시계) + 웹캠 또는 세 번째 폰
B       : dev1 + 아이폰1 (핫스팟 켜고, 삼각대에 세워 계속 녹화)
C       : dev2 + 아이폰2 (핫스팟 켜고, 삼각대에 세워 계속 녹화)
```

1. B, C에 노드와 폰을 두고 **녹화 시작 후** 자리를 뜬다. 노드가 초록(온라인)이고 `buzz:ok` 접속 알림이 울리는지 확인.
2. A로 이동해 `bash console.sh`를 띄운 터미널을 화면 녹화하며 에피소드를 순서대로 말한다. 한 에피소드 사이에 **5초 이상 침묵**을 둔다(편집 시 자르기 쉽게).
3. 끝나면 B, C 영상을 회수한다.
4. **싱크 기준**: console.sh의 타임스탬프가 정답이다. 각 폰 영상 시작 직후 폰 화면의 시계를 한 번 찍어두거나, A에서 첫 명령으로 `all buzz:ok`를 보내 세 곳에서 같은 소리가 나게 해 두면 그 소리를 기준으로 맞춘다.

사전 리허설(촬영 전날):
```
bash fleet.sh                 # 세 노드 ONLINE, 망 이름이 각각 다른지
bash dev.sh dev1 caps         # caps:led,ping,servo,poke,relay,fan,buzz 나오는지
bash dev.sh dev2 poke:120:600 # 풍선 각도 확인 (풍선 없이 먼저)
bash dev.sh dev1 relay:pulse:1000   # 자기 전원 끊고 되살아나는지, 다이진이 보고하는지
```

## 4. 편집: 초보자 코스

**도구는 iMovie(설치돼 있음) 하나로 충분하다.** 자막은 iMovie 타이틀, 2분할은 "분할 화면" 오버레이. 3분할이 필요한 컷만 아래 ffmpeg로 만들어 iMovie에 가져온다.

세 영상을 가로로 붙이기(각 영상의 싱크 오프셋을 `-ss`로 맞춘다, 예: A는 3.2초, B는 0초, C는 1.7초 지점부터):
```bash
ffmpeg -ss 3.2 -i A.mov -ss 0 -i B.mov -ss 1.7 -i C.mov \
  -filter_complex "[0:v]scale=640:-2[a];[1:v]scale=640:-2[b];[2:v]scale=640:-2[c];[a][b][c]hstack=3[v]" \
  -map "[v]" -map 0:a -c:v libx264 -crf 20 -c:a aac -shortest triptych.mp4
```

지연을 다루는 원칙: **자르지 말고 보여준다.** 명령 후 응답까지의 공백에는 관제 화면(생각 중 / 명령 발행 / ACK)을 크게 넣고 자막으로 `+7.4s`처럼 실제 시간을 찍는다. 개발자가 보는 영상에서 정직한 지연 표기는 감점이 아니라 신뢰다. 다만 20초 넘게 비는 구간은 점프컷으로 줄이고 자막에 "(12초 생략)"이라고 쓴다.

자동 자막이 필요하면 CapCut 데스크톱(무료, 한국어 자동 자막)에 최종 mp4를 넣어 자막만 얹고 다시 내보내는 게 제일 빠르다.

## 5. 60~90초 대본 초안

| 시간 | 화면 | 소리 |
|---|---|---|
| 0~5s | 검은 화면, 자막 "다이진은 장난꾸러기 신이다" | daijin 준비 차임 |
| 5~20s | A: 나 "다이진, 회사 와이파이 꺼버려" / 3분할로 B의 dev1 LED가 죽는다 | 다이진 "알았어" → 잠시 후 "dev1이 오프라인 됐어… 어, 다시 돌아왔네. 재부팅했나 봐" |
| 20~35s | A: "상사 차 진짜로 펑크 내" → 거절 → "풍선은 터뜨려 줄게" / C: 풍선 펑 | 펑 소리를 컷 포인트로 |
| 35~45s | A: "다들 어디 있어?" / 관제 화면에 세 노드의 망 이름 | 다이진이 위치를 읊는다 |
| 45~55s | A: "전부 불 꺼" / 3분할 동시에 꺼짐 | 자막: "한 토픽, 세 망, 세 장소" |
| 55~70s | 아키텍처 한 장(README 그림) 위에 자막 3줄: 아웃바운드 TLS만 / EU 브로커 300ms / ADPCM 4:1 | 다이진 "오늘 수고했어" |
| 70~80s | 깃허브 주소, "Built with Claude Code" | 끝 |
